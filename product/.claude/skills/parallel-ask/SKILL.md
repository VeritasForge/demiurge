# 질문 병렬 처리

워커는 이 대화를 그대로 상속한다. 지금까지 읽은 파일, 측정한 수치, 합의한 결정은 이미 워커 안에 있다. 프롬프트로 옮길 배경이 없다.

## 실행

**1. 질문 분리** — `$ARGUMENTS`에서 번호(`1.` `2.`)나 줄바꿈을 경계로 질문을 나눈다. 질문 1개 = 워커 1개. 판단을 요구하는 질문도 워커에게 보낸다 — 워커에게 근거와 선택지를 받고 결론은 내가 낸다.

**2. 사전 확인** — `subagent_type: "fork"`를 쓸 수 없으면 디스패치하지 말고 멈춘다. `CLAUDE_CODE_FORK_SUBAGENT=1`이 적용되지 않은 세션이라는 뜻이므로, 사용자에게 Claude Code 재시작이 필요하다고 알린다.

**3. 동시 디스패치** — 질문 수만큼 `Agent` 호출을 **한 메시지에** 넣는다. 각 호출:

- `subagent_type`: `"fork"`
- `description`: 질문을 5단어 이내로 요약
- `prompt`: 아래 세 줄을 그대로 채운다

```
질문: <질문 원문 하나>
범위: 읽기·검색·웹 조사만. 파일 수정 금지.
반환: 결론 1~3문장 → 근거(파일:라인 또는 URL) → 미확인 항목.
```

**4. 턴 종료** — fork 모드에서는 모든 워커가 백그라운드로 돌고 `run_in_background` 파라미터가 없다. 디스패치한 그 메시지로 턴을 끝낸다. 결과가 오기 전에 답을 만들거나 진행 상황을 추측하지 않는다.

**5. 종합** — 완료 알림이 전부 도착한 뒤 질문별 답과 미확인 항목을 정리한다. 근거가 붙지 않은 주장은 옮기지 않는다.

## 쓰지 않을 때

질문이 하나일 때. 워커 없이 직접 답한다.
