# autopilot — 사람 없이 완주하고, 판단을 남기는 스킬

밤에 걸어두고 아침에 결과를 검토하기 위한 스킬입니다.
목표에 도달할 때까지 스스로 작업을 이어가고, 그 과정에서 내린 판단을 사람이 읽을 형태로 남깁니다.

## 무엇을 해결하는가

자율 실행에는 두 가지 실패가 있습니다.

- 완주는 했는데 **어떤 판단을 거쳐 거기 도달했는지 알 수 없는** 경우. 검토가 불가능합니다.
- 판단마다 사람에게 물어서 **결국 사람이 붙어 있어야 하는** 경우. 자율이 아닙니다.

이 스킬은 판단을 미루지 않고 스스로 내리되, **사람에게 물으려 했던 순간을 전부 기록**해서
아침에 그 목록부터 볼 수 있게 합니다.

## 쓰는 법

```
/autopilot <플랜 경로>
/autopilot "<목표 설명>"
```

호출하면 스킬이 목표를 읽고 완료조건을 한 줄로 만들어 제시합니다.
그 줄을 그대로 복사해 입력하면 사람 입력 없이 턴이 자동으로 이어집니다.

```
/goal <제시된 조건 문장>
```

**이 스킬은 `/goal`을 스스로 걸 수 없습니다.** 사용자가 입력해야 합니다.
걸지 않으면 한 턴만 진행하고 안내를 출력한 뒤 멈춥니다.

상태 확인은 인자 없이 `/goal`, 해제는 `/goal clear` 입니다.

## 두 가지 모드

작업의 성격을 스스로 판별합니다. 기준은 하나입니다.

> 무엇이 맞는지 기계적으로 판정할 수 있는가?

| 판정 | 산출물 | 모드 |
|---|---|---|
| 가능 | 코드 | **만들기** — 테스트를 먼저 쓰고, 검증 명령으로 완료를 판정합니다 |
| 가능 | 문서·결론 | **알아내기** — 세 축으로 조사하고, 출처 수와 반박 처리로 완료를 판정합니다 |
| 불가능 | — | **자율 실행에 넣지 않습니다.** 목표를 좁힌 뒤 다시 부릅니다 |

세 번째가 중요합니다. "무엇을 만들지 아직 모르는" 탐색 단계는 자율 루프에 넣으면
수렴하지 않고 비용만 씁니다. 이건 이 스킬의 한계가 아니라 자율 실행 방식 자체의 성질입니다.

두 모드가 섞인 작업(조사해서 근거를 세운 뒤 그것으로 만드는 작업)은
알아내기로 시작해 결론이 서면 만들기로 넘어갑니다.

## 플랜은 필요할 때만

플랜 파일이 꼭 있어야 동작하지 않습니다.

- 플랜을 주면 그것을 따릅니다.
- 안 주었는데 여러 단계로 나뉘고 순서 의존이 있으면 **계획부터 직접 만듭니다.**
- 안 주었고 목표가 단일하면 계획 없이 바로 진행합니다.

## 만들어지는 파일

작업 폴더는 `docs/autopilot/<작업이름>/` 입니다.

| 파일 | 무엇인가 |
|---|---|
| `STATE.md` | 매 턴 처음에 읽고 마지막에 갱신하는 파일. 확정한 것, 기각한 것, 다음에 할 일 |
| `DECISIONS.md` | 판단 기록. 사람이 읽을 형태로 계속 덧붙입니다 |
| `DIGEST.md` | 완주 후 한 페이지 요약. **아침에 이것부터 여세요** |
| `BLOCKED.md` | 막혔을 때만 생깁니다 |

같은 이름으로 다시 호출하면 폴더가 남아 있으므로 **이어서** 진행합니다.

## 아침에 무엇을 하면 되는가

1. `DIGEST.md`를 엽니다.
2. **"한 번 더 봐주세요"** 절을 먼저 봅니다. 원래 사람에게 물으려던 결정이 전부 여기 올라옵니다.
   스킬이 확신했더라도 올라옵니다.
3. 잘못된 판단이 있으면 코드를 고치고, 같은 실수가 반복될 만한 것이면 규칙에 반영합니다.
   반영할 곳은 프로젝트의 `CLAUDE.md`, 규칙 파일, 또는 이 스킬 자체입니다.
4. `BLOCKED.md`가 있으면 그 결정을 내려주고 다시 호출합니다.

## 설계상 하지 않는 것

| 하지 않음 | 이유 |
|---|---|
| 실행 중 질문 카드를 띄우는 것 | 띄우는 순간 자율이 끝납니다. 대신 물으려던 질문과 세운 가정을 기록합니다 |
| 원격 푸시 | 명시적으로 허용했을 때만 합니다. 기본은 커밋까지입니다 |
| 되돌리기 어려운 작업 | 배포·외부 전송·대량 삭제는 자율 실행 중에 하지 않고 막힘으로 처리합니다 |
| 본체를 격리 실행 | 과정이 대화에 남지 않으면 완료 판정이 되지 않습니다 |

## 알아둘 제약

- **완료를 판정하는 쪽은 명령을 실행하거나 파일을 읽지 못합니다.** 대화에 글로 남은 것만 봅니다.
  그래서 이 스킬은 매 턴 마지막에 증거를 대화 본문에 요약합니다.
- **대화가 길어지면 스킬 본문이 잘려나갑니다.** 그래서 매 턴 처음에 상태 파일을 다시 읽습니다.
  중요한 규칙일수록 파일 앞쪽에 배치되어 있는 것도 같은 이유입니다.
- **`/goal`이 걸려 있으면 스스로 멈추기 어렵습니다.** 그래서 완료조건에 막힘 탈출 절을
  반드시 넣습니다. 그 절이 없으면 막혀도 계속 재시작됩니다.
