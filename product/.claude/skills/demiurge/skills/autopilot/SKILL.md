# Autopilot — 사람 없이 완주하고, 판단을 남긴다

빠른 완주만 있으면 잘못된 판단이 그대로 쌓이고, 기록만 있으면 사람이 계속 붙어 있어야 한다.
둘을 함께 한다.

---

## 0. 되돌릴 수 없는 일은 하지 않는다

이 절을 맨 앞에 둔 이유가 있다. 대화가 길어지면 이 문서는 **뒤에서부터 잘려나간다**(§1).
다른 규칙은 잃으면 비효율이 생기지만, 이 규칙을 잃으면 **되돌릴 수 없는 사고**가 난다.

자율 실행 중에 하지 않는 것:

- **원격 푸시.** 커밋까지만 한다. 사용자가 명시적으로 허용했을 때만 예외다.
- **배포**, 마이그레이션 실행, 외부로 데이터 전송, 대량 삭제.
- 사용자 계정·비밀·결제와 관련된 변경.

이런 작업이 목표에 포함되어 있으면 **거기서 막힘으로 처리하고 멈춘다**(§4).
"사용자가 자율로 하라고 했으니 포함된 것 아닌가"는 근거가 되지 않는다.
자율은 판단을 대신하라는 뜻이지, 되돌릴 수 없는 결과를 대신 감수하라는 뜻이 아니다.

## 1. 매 턴 맨 처음에 상태 파일을 읽는다 (건너뛰지 말 것)

대화가 길어지면 이 스킬의 본문이 **잘려나간다.** 프로그램이 직접 알려주는 문구가 있다.

> `[... skill content truncated for compaction; use Read on the skill path if you need the full text]`

밤새 도는 작업은 거의 확실히 이 상황을 겪는다. 그래서 매 턴의 첫 행동은 고정이다.

```bash
# 이 작업의 폴더를 먼저 찾는다. 이름을 모르는 상태에서도 실행할 수 있어야 한다.
find <base>/docs/autopilot -maxdepth 2 -name STATE.md 2>/dev/null
```

- 나온 것 중 지금 목표와 맞는 것이 있으면 **그 파일을 읽고 이어서 한다.**
- 하나도 없거나 맞는 것이 없으면 이번이 **첫 턴**이다. 아래 §6 진입 절차로 간다.

읽었는데 규칙이 기억나지 않으면 이 파일(`SKILL.md`)도 다시 읽는다. 다시 읽는 것이 정상 절차다.

경로 표기 규칙: 이 문서에서 `<base>`는 §6에서 정하는 저장소 최상위 경로다.
**완료조건 문장 안에서는 `<base>`를 빼고 상대경로로 쓴다.** 판정하는 쪽은 파일을 열지 않으므로
절대경로가 아무 의미가 없고, 문장만 길어진다.

그리고 매 턴의 **마지막 행동**은 `STATE.md` 갱신이다. 파일에 적지 않은 것은 다음 턴에 존재하지 않는다.

## 2. STATE.md 형식 (자유 서술 금지)

형식을 고정하는 것 자체가 효과를 낸다. 한 연구에서 같은 구조를 자유 서술로 바꾸자 성능이 떨어졌다.

```markdown
# 상태 — <작업 이름>
- 모드: 만들기 | 알아내기 | 알아내기 → 만들기(전환 예정)
- 목표: <한 문장>
- 완료조건: <사용자에게 제시한 조건 문장 그대로>
- 턴: <N>
- 계획 파일: <있으면 경로. 없으면 줄 자체를 생략>
- 출처 목록: <알아내기 모드일 때만. SOURCES.md 경로와 확인/미확인 건수>

## 확정된 것
- [확정] <사실> — 근거: <출처 한 줄>

## 기각한 것
- [기각] <검토했다 아니라고 본 방향> — 이유: <왜 아닌지 한 줄>

## 보류
- [보류] <판정 못 한 것> — 필요한 것: <무엇이 있어야 판정되는지>

## 다음에 할 일
- [ ] <다음 턴이 가장 먼저 할 일>

## 주의
- <이 작업에서 반복해서 틀렸던 것>
```

**기각 목록을 빠뜨리지 말 것.** 확정된 것만 남기면 다음 턴이 같은 막다른 길을 다시 간다.
자율 실행의 대표적 실패는 새로운 실수가 아니라 **같은 시도의 반복**이다.

**60줄을 넘기면 압축한다.** 확정과 기각은 남기고 근거 설명을 줄인다.
누적물이 커지면 이후 모든 턴의 컨텍스트를 갉아먹고, 낡은 항목이 잘못된 판단을 유도한다.

압축할 때 **기각 항목의 이유는 지우지 않는다.** 이유가 없는 기각은 다음 턴이
"왜 아니었지?" 하며 다시 시도하게 만들어, 목록을 유지한 의미가 사라진다.
줄일 것은 확정 항목의 근거 설명이다.

알아내기 모드는 확인한 출처가 빠르게 늘어 이 상한과 부딪친다.
그래서 출처 목록은 `STATE.md`에 두지 않고 별도 파일로 뺀다(`mode-research.md` 참조).

## 3. 완료조건은 대화에서 확인 가능해야 한다

완료 여부를 판정하는 쪽은 **명령을 실행할 수 없고 파일도 읽을 수 없다.** 대화에 글로 남은 것만 본다.
게다가 대화가 길면 앞부분이 잘리고, 잘린 경우 "증거가 부족하다"고 답하도록 지시받는다.

여기서 세 가지가 따라 나온다.

1. **조건은 500자 이내**로, 대화에서 확인 가능한 형태로 쓴다.
2. **막힘 탈출 절을 반드시 넣는다.** 없으면 막혀도 멈추지 못하고 계속 재시작된다.
3. **매 턴 마지막에 증거를 대화 본문에 요약한다.** 파일에만 적으면 판정에 쓰이지 않는다.

**"파일이 생성되었음"을 조건에 쓰지 말 것.** 판정하는 쪽은 파일을 열 수 없으므로
그 절은 영원히 확인되지 않는다. 파일을 만들라는 요구는 그대로 두되, 조건에는
**그 내용이 대화에 보고되었는가**를 쓴다.

형식은 두 모드가 같다.

```
<측정 가능한 종료 상태> 이고,
<산출물 경로>의 핵심 내용(<무엇을 요약할지>)이 대화 본문에 보고되었음
— 또는 docs/autopilot/<slug>/BLOCKED.md 의 막힌 사유가 대화 본문에 보고되었음.
```

경로는 저장소 최상위 기준 상대경로로 쓴다.

조건을 만들었으면 사용자에게 그대로 붙여넣을 한 줄로 제시한다.

```
🚦 자율 완주를 걸려면 다음을 그대로 붙여넣으세요 →
   /goal <조건 문장>
ℹ️ 상태 확인: 인자 없이 /goal · 해제: /goal clear
```

**이 스킬은 `/goal`을 걸 수도, 해제할 수도, 걸려 있는지 조회할 수도 없다.**
셋 다 사용자만 할 수 있다. 그래서 이렇게 동작한다.

- 안내를 출력하고 **이번 턴 할 수 있는 데까지 진행한 뒤 끝낸다.**
- 조건이 걸려 있었다면 다음 턴이 저절로 시작된다. 그때 §1부터 이어가면 된다.
- 걸려 있지 않았다면 거기서 멈춘 것이고, 사용자가 안내를 보고 입력하면 된다.

즉 **걸림 여부를 알아내려 하지 않는다.** 알 수 없고, 알 필요도 없다.

### 조건이 깨져 있을 때 (헛돌지 말 것)

작업을 마쳤는데도 턴이 다시 시작되고, 판정 사유가 "조건이 유효하지 않다"거나
조건 문장이 목표와 무관한 말(예: `again to continue.`)이면 **조건이 깨진 것이다.**

이 상태는 자율로 복구되지 않는다. 사람이 `/goal clear`를 입력해야 한다.
같은 보고를 반복하면 진행 없는 턴이 쌓여 강제 중단될 때까지 헛돈다. 대신 이렇게 한다.

1. 깨졌다는 사실과 복구 방법(`/goal clear`)을 대화에 **한 번만** 적는다. 매 턴 반복하지 않는다.
2. 남은 턴을 **원래 목표에 이어지는 실제 작업**에 쓴다.
   검증하지 않은 부분을 검증하거나, 미룬 항목을 처리하거나, 기록을 보강한다.
3. 그마저 없으면 `STATE.md`에 "완료. 사람의 조건 해제 대기"를 적고 짧게 끝낸다.

## 4. 막혔을 때

결정할 수 없거나, 외부 의존이 풀리지 않거나, 요구가 서로 모순될 때.

1. `<base>/docs/autopilot/<slug>/BLOCKED.md` 를 쓴다. 사유 분류(결정 불가 / 외부 의존 / 모순),
   시도한 것, 사람에게 필요한 결정을 각각 적는다.
2. **그 사유를 대화 본문에도 한 문단으로 옮긴다.** 판정하는 쪽은 파일을 못 읽는다.
   여기를 빠뜨리면 완료조건의 탈출 절이 작동하지 않아 루프가 헛돈다.
3. 멈춘다.

## 5. 판단할 때 지키는 네 가지

1. **학습한 내용만 믿지 않는다.** 1차 출처(문서·코드·실행 결과)를 연 뒤에 단정한다.
   경로를 언급하기 전에 `ls`나 `Grep`으로 실존을 확인한다.
2. **결론을 서두르지 않는다.** 의심스러우면 자료를 더 본다.
3. **의견이 갈릴 결정은 경합시킨다.** 관점이 다른 담당자를 `Agent`로 띄우되,
   **한 명에게는 반대 결론을 입증하도록 맡긴다.** 내가 이미 기운 방향이 있으면
   그 편향은 반대 담당을 세워야만 드러난다.
   경합은 **사실 확인이 끝나고 결론 후보가 생긴 뒤에** 한다.
   전제(어떤 기술을 쓰는지, 코드가 실제로 어떻게 되어 있는지)를 모른 채 경합시키면
   양쪽 다 "그건 상황에 따라 다르다"로 끝나 결론의 절반이 버려진다.
   진입 단계에는 반박할 대상이 없으므로 `STATE.md`의 `## 주의`에
   "어떤 결정에 반대 담당을 세울지"만 적어두고 넘어간다.
4. **사람에게 물어보고 싶어지는 순간이 곧 기록해야 할 순간이다.**

네 번째를 구체적으로 적는다. 자율 실행 중에는 질문 카드를 띄우지 않는다. 대신 스스로 결정하되,
`DECISIONS.md`에 다음 두 칸을 **반드시** 채운다.

```
원래 물으려던 것: <사람에게 던졌을 질문>
세운 가정: <대신 무엇을 전제하고 진행했는지>
```

이 두 칸이 채워진 항목은 **확신도와 무관하게** 요약 문서의 "한 번 더 봐주세요"에 올린다.
스스로 확신했다고 해서 빼면, 사람은 자기 몫이었던 결정을 영영 못 보게 된다.

## 6. 진입 절차 (첫 턴에만)

1. **기준 디렉토리**: `git rev-parse --show-toplevel 2>/dev/null || pwd`
2. **작업 이름(slug)**: 플랜 파일 이름 → 없으면 목표의 핵심어. 소문자·하이픈·30자 이내.
3. **폴더 생성**: `mkdir -p <base>/docs/autopilot/<slug>`
   이미 있으면 **이전 실행의 재진입**이다. `STATE.md`를 읽어 이어서 한다.
4. **지난 실행의 교훈을 읽는다** (§6-1)
5. **모드 판별** (§7)
6. **플랜 처리** (§8)
7. **완료조건 생성 및 안내** (§3)
8. `STATE.md` 최초 작성

## 6-1. 지난 실행의 교훈을 읽는다

상태 파일은 **같은 작업 안에서만** 기억을 잇는다. 다른 작업을 새로 시작하면 그 기억은 없다.
그래서 진입할 때 형제 폴더들이 남긴 교훈을 한 번 훑는다.

```bash
# 지난 실행들이 남긴 "다음 사람이 알아야 할 것"만 뽑아 읽는다.
# find를 쓰는 이유: 셸에 따라 매치가 없는 글로브(*/DIGEST.md)가 에러로 끝난다.
# awk를 쓰는 이유: 그 절이 문서 마지막이면 sed 범위의 종료 패턴이 영영 안 나타난다.
find <base>/docs/autopilot -maxdepth 2 -name DIGEST.md 2>/dev/null | while read -r f; do
  echo "--- $f"
  awk '/^## 📌 다음 사람이 알아야 할 것/{f=1;print;next} f&&/^## /{exit} f{print}' "$f"
done
```

**전문을 읽지 않는다.** 요약본의 해당 절만 본다. 누적물을 통째로 되먹이면
컨텍스트를 갉아먹고 낡은 항목이 잘못된 판단을 유도한다.

읽은 것 중 이번 작업에 해당하는 항목이 있으면 `STATE.md`의 `## 주의`에 옮겨 적는다.
옮기지 않으면 다음 턴에 사라진다.

폴더가 없거나 요약본이 없으면 그냥 넘어간다. **없다고 멈추지 않는다.**

## 7. 모드 판별

질문 하나로 정한다.

> **무엇이 맞는지 기계적으로 판정할 수 있는가?**

| 판정 가능? | 산출물 | 결과 |
|---|---|---|
| 가능 | 코드 | **만들기 모드** → `references/mode-build.md` 를 읽는다 |
| 가능 | 문서·결론 | **알아내기 모드** → `references/mode-research.md` 를 읽는다 |
| 불가능 | — | **자율 실행에 넣지 않는다.** 사람과 대화로 목표를 좁힌 뒤 다시 부른다 |

세 번째를 무시하지 말 것. 목표가 모호하면 루프는 수렴하지 않고 비용만 쓴다.
"UI를 세련되게" 같은 주관적 목표가 여기 해당한다.

**모드는 최종 산출물로 정한다. 도중에 무엇을 하는지로 정하지 않는다.**
이 구분이 없으면 다음 두 경우에서 헷갈린다.

| 상황 | 모드 | 참조 파일 |
|---|---|---|
| 산출물이 코드인데 플랜이 없다 | **만들기** | `mode-build.md` 하나만 |
| 위에서 계획을 먼저 세우는 단계 | 여전히 **만들기** | 모드가 바뀌는 것이 아니라, 만들기의 첫 단계다 |
| 조사로 근거를 세운 뒤 그 근거로 만든다 | **알아내기로 시작 → 만들기로 전환** | 시작은 `mode-research.md`, 전환 후 `mode-build.md` |

세 번째 줄만 모드가 바뀐다. 이때 `STATE.md`의 모드 줄을 `알아내기 → 만들기` 로 적고,
전환 시점에 실제로 갱신한다. 나머지는 처음부터 끝까지 한 모드다.

판별 결과는 `STATE.md` 맨 앞에 적어 사람이 즉시 확인할 수 있게 한다.

## 8. 플랜은 필요할 때만 만든다

플랜 경로가 인자로 주어지면 읽고, 그것을 따른다. 없을 때는 모드에 따라 다르다.

**만들기 모드에서 플랜이 없을 때**

- 작업이 여러 단계로 나뉘고 **순서 의존이 있으면** 계획 파일을 먼저 만든다.
  이 단계에서는 **구현하지 않는다.** 계획 파일 경로를 `STATE.md`에 적는다.
- 목표가 단일하면 계획 없이 진행한다.

계획 파일을 어디에 둘지: **프로젝트에 이미 플랜을 모으는 폴더가 있으면 그곳에 둔다.**
없으면 작업 폴더 안의 `PLAN.md`로 만든다. 기존 관례가 있는데 작업 폴더에 따로 만들면
그 프로젝트에서 플랜을 찾는 사람이 못 찾는다.

**알아내기 모드에서 플랜이 없을 때**

별도의 계획 파일을 만들지 않는다. 조사는 무엇을 찾을지 모른 채 시작하므로
목록을 미리 확정할 수 없다. 대신 `STATE.md`의 `## 아직 안 본 것` 이 계획 역할을 한다.
확인할 대상이 떠오를 때마다 거기에 추가하고, 확인하면 옮긴다.

## 9. 기록물

```
docs/autopilot/<slug>/
├── STATE.md       매 턴 읽고 쓴다. 60줄 상한
├── DECISIONS.md   판단을 사람이 읽을 형태로 누적 (덧붙이기만)
├── DIGEST.md      완주 후 한 페이지 요약 (덮어쓰기)
├── SOURCES.md     알아내기 모드에서만. 확인한 출처. 상한 없음
├── PLAN.md        계획을 직접 만들었고 프로젝트에 플랜 폴더가 없을 때만
└── BLOCKED.md     막혔을 때만
```

앞의 셋은 항상 만든다. 뒤의 셋은 해당할 때만 만든다.

**각 문서의 서식은 `references/formats.md` 에 있다. 글을 쓰기 직전에 읽어라.**
서식을 본문에 두지 않은 이유는, 쓸 때만 필요한 내용이 매 턴 자리를 차지하면
정작 매 턴 필요한 규칙이 뒤로 밀려 압축 때 먼저 잘리기 때문이다.

기억해야 할 것은 서식이 아니라 이것 하나다. **판단 기록에 "원래 물으려던 것"과
"세운 가정"이 채워진 항목은, 확신도와 무관하게 요약 문서의 검토 권고 절에 올린다**(§5).

## 10. 커밋

되돌릴 수 없는 일에 대한 경계는 §0에 있다. 여기는 커밋에 관한 것만 적는다.

- 커밋은 한다. 각 의미 단위마다 한 번. 그것이 되돌리기 단위가 된다.
- 커밋 메시지 공동저자 줄은 **현재 세션 모델 이름**으로 적는다. 특정 버전을 박아두지 않는다.
- 푸시는 하지 않는다(§0).

## 11. 하지 않는 것

| 하지 않는 것 | 이유 |
|---|---|
| 질문 카드를 띄우는 것 | 자율 실행의 전제를 깬다. 대신 §5의 두 칸을 채워 기록한다 |
| 이 스킬 본문을 격리 실행으로 돌리는 것 | 과정이 본 대화에 안 남아 완료 판정이 영구히 미충족이 된다. 부분 작업만 격리하고 결과 요약은 본 대화에 옮긴다 |
| 작업 목록 도구 사용 | 이 환경에 없다. `STATE.md`의 체크박스로 대신한다 |
| 외부 학습 도구 이름을 절차에 박는 것 | 이름이 바뀌거나 등록되지 않으면 끊긴다. 자기 폴더의 파일이 기본이고, 외부 도구는 있으면 쓰는 선택지다 |

## 12. 스스로를 의심해야 할 신호

아래 생각이 들면 그 순간이 규칙을 건너뛰려는 순간이다.

| 떠오른 생각 | 실제 상황 |
|---|---|
| "이건 너무 명백해서 출처 확인은 불필요하다" | 명백함은 검증이 아니다. 한 줄이라도 열어본다 |
| "조사는 토큰 낭비다" | 잘못된 결정 하나를 되돌리는 비용이 더 크다 |
| "사람한테 물어보면 빠른데" | 물어보는 순간 자율은 끝난다. 가정을 세우고 기록한다 |
| "기록은 나중에 몰아서" | 갱신 안 된 상태 파일은 다음 턴에 없는 것과 같다 |
| "어차피 사람이 요약에서 잡아줄 것" | 요약에 올리는 것도 이 절차의 일이다 |
| "이전에 시도했던 것 같지만 다시 해보자" | 기각 목록을 먼저 읽는다. 같은 시도의 반복이 가장 흔한 낭비다 |
