# 만들기 모드

무엇이 맞는지를 검증 명령으로 판정할 수 있고, 산출물이 코드인 작업.

`SKILL.md`의 공통 규칙(상태 파일, 완료조건, 판단 네 가지, 기록물)은 그대로 적용된다.
아래는 이 모드에서만 다른 것이다.

---

## 1. 한 턴에 한 덩어리

한 턴에서 여러 작업을 동시에 진행하지 않는다. 하나를 끝내고 검증하고 커밋한 뒤 다음으로 간다.
중간에 대화가 압축되어도 커밋과 상태 파일이 남아 있으면 이어서 할 수 있다.

작업 목록은 `STATE.md`의 체크박스로 관리한다. 플랜 파일이 있으면 그 파일의 체크박스를 갱신한다.

## 2. 일꾼 배분

- **읽기와 검색**은 넓게 병렬로 돌려도 된다.
- **빌드와 테스트를 실행하는 일꾼은 하나만 둔다.** 여럿이 동시에 돌면 산출물 디렉토리와
  포트가 충돌해 실패 원인을 오진하게 된다.

## 3. 구현 순서

1. **고칠 것이 무엇인지 먼저 확인한다.** 없다고 가정하지 말고 `Grep`으로 찾는다.
   있는 것을 없다고 판단해 중복 구현하는 것이 가장 흔한 실수다.
2. **테스트를 먼저 쓴다.** 정상 경로·경계값·오류 상황을 각각 최소 하나씩.
3. 테스트가 실패하는 것을 확인한 뒤 구현한다.
4. 검증 명령을 돌린다.
5. 리뷰한다.
6. 커밋한다.

## 4. 검증

프로젝트가 실제로 쓰는 명령을 확인해서 쓴다. 추측하지 않는다.
`package.json`의 스크립트, `Makefile`, `justfile`, `pyproject.toml` 등을 먼저 연다.

```
예: pnpm typecheck && pnpm lint && pnpm test && pnpm build
예: pytest && ruff check && mypy .
예: cargo test && cargo clippy
```

**결과를 대화 본문에 요약해 남긴다.** 완료를 판정하는 쪽은 명령을 실행할 수 없고
대화에 남은 글만 본다. 파일에만 적으면 판정에 쓰이지 않는다.

```
검증: typecheck 0 / lint 0 / test 0 (312건 통과) / build 0
```

## 5. 리뷰

의미 있는 변경마다 최소 한 번 리뷰를 거친다. 발견된 중대 결함이 없어질 때까지 고치고 다시 본다.

리뷰 전용 스킬이 설치되어 있으면 `Skill` 도구로 부른다. 없으면 직접 읽고 판단한다.
**있으면 쓰고 없으면 건너뛴다.** 특정 스킬 이름에 절차를 의존시키지 않는다.
이름이 바뀌거나 등록되어 있지 않으면 그 단계가 통째로 실패하기 때문이다.

- React·Next.js 코드는 리뷰 기준에 Vercel 권장 사항을 포함한다.
- 리뷰에서 나온 지적을 그대로 받지 않는다. 근거가 약하면 그 근거를 확인한 뒤 판단한다.
  받아들이지 않기로 한 지적도 `DECISIONS.md`에 이유와 함께 남긴다.

## 6. 커밋 경계

- 의미 단위마다 커밋한다. 한 커밋이 되돌리기 단위가 된다.
- **원격 푸시는 사용자가 명시적으로 허용했을 때만 한다.**
- 마이그레이션, 배포, 외부 전송, 대량 삭제처럼 되돌리기 어려운 작업은 자율 실행 중에 하지 않는다.
  필요하면 `BLOCKED.md`에 적고 멈춘다.

## 7. 완료조건 쓰는 법

```
계획된 모든 작업이 끝나고, <검증 명령들>이 각각 종료코드 0으로 끝난 출력이 대화에 남아 있으며,
검토가 필요한 판단과 남은 위험이 대화 본문에 요약 보고되었음
— 또는 docs/autopilot/<slug>/BLOCKED.md 의 막힌 사유가 대화 본문에 보고되었음.
```

요약 문서는 물론 만든다. 다만 **조건에 "문서가 생성되었음"을 쓰지 않는다.**
판정하는 쪽은 파일을 열 수 없어서 그 절은 영영 확인되지 않는다.

## 8. 이 모드에서 자주 나는 사고

| 사고 | 막는 법 |
|---|---|
| 이미 있는 기능을 없다고 보고 다시 만든다 | 만들기 전에 반드시 검색한다 |
| 테스트가 깨진 채로 다음 작업에 들어간다 | 깨진 상태로는 넘어가지 않는다. 깨진 토대 위에 쌓으면 원인 추적이 불가능해진다 |
| 검증 없이 "된 것 같다"고 넘어간다 | 종료코드를 눈으로 확인하고 대화에 적는다 |
| 요청하지 않은 개선을 함께 한다 | 바꾼 줄이 전부 요청과 이어지는지 확인한다. 곁가지 발견은 문서에 적기만 한다 |
| 할 일이 없는데 테스트만 반복해 돌린다 | 남은 작업이 없으면 완료 요약을 쓰고 끝낸다 |
