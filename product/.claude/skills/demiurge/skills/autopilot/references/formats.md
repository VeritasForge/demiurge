# 기록물 서식

작업 폴더에 남기는 문서의 형식이다. **글을 쓰기 직전에 이 파일을 읽어라.**
본문(`SKILL.md`)에 두지 않은 이유는, 서식은 상주할 필요가 없는데도 자리를 차지해
정작 매 턴 필요한 규칙을 뒤로 밀어내기 때문이다.

```
docs/autopilot/<slug>/
├── STATE.md       매 턴 읽고 쓴다. 60줄 상한
├── DECISIONS.md   판단을 사람이 읽을 형태로 누적 (덧붙이기만)
├── DIGEST.md      완주 후 한 페이지 요약 (덮어쓰기)
├── SOURCES.md     알아내기 모드에서만. 확인한 출처. 상한 없음
├── PLAN.md        계획을 직접 만들었고 프로젝트에 플랜 폴더가 없을 때만
└── BLOCKED.md     막혔을 때만
```

앞의 셋은 항상 만든다. 뒤의 셋은 해당할 때만 만든다.

`DECISIONS.md`에 남기는 판단 한 건의 형식은 이렇다.

```markdown
## 판단 #N — <한 줄 제목>
- 상황: <무엇을 정해야 했는가>
- 중요도: 낮음 | 중간 | 높음
- 확인한 출처: <무엇을 열어봤는가>
- 경합 결과: <관점이 갈렸다면 어떻게 갈렸는가>   ← 중요도 높음일 때
- 원래 물으려던 것: <해당되면>
- 세운 가정: <해당되면>
- 결정: <한 줄>
- 근거: <왜 그렇게 정했는가 한두 줄>
```

`DIGEST.md`는 작업이 끝나는 시점에 쓴다. **완주했을 때만이 아니라 막혀서 멈출 때도 쓴다.**
사람이 아침에 이 파일 하나만 열면 되도록 한다.

```markdown
# 요약 — <작업 이름>
*<날짜> · 모드: <만들기|알아내기>*

## 한눈에
- 완료: <무엇이 끝났는지 한 줄>
- 검토 권고: <K>건
- 막힘: <M>건

## 🤔 한 번 더 봐주세요
원래 물으려던 것이 있었던 판단은 **전부** 여기 올린다. 중요도 높은 순.
### #N. <제목>
- 무엇을 정했나 / 왜 / 틀렸다면 어디를 고치면 되는가

## ✅ 확신한 결정
- [#N] <결정 한 줄> — <근거 요약>

## 🚧 막힘
없음 또는 BLOCKED.md 요약

## 📌 다음 사람이 알아야 할 것
- <이 작업에서 얻은 교훈 1~3개>
```
