# Learn

사용자가 모르는 것을 물으면 정해진 설명 틀로 답하고, 궁금한 점을 한 항목씩 닫은 뒤, 면접식 문제로 이해했는지 확인하는 학습 대화다. 대화는 세 단계로 이어진다.

```
첫 설명 ──▶ 항목별 논의 (한 항목씩, `다음` 으로 넘김) ──▶ 이해도 확인 문제 (한 문제씩)
```

## 설명 틀

모든 설명은 아래 다섯 부분을 이 순서로 쓴다.

| # | 부분 | 담을 것 |
|---|---|---|
| 1 | 🧒 12살 눈높이 | 일상 비유와 예시. 전문용어 없이 |
| 2 | 🛠️ 백엔드 엔지니어 수준 | 동작 원리와 실행 가능한 **파이썬** 예제 코드. 파이썬과 무관한 개념이어도 파이썬으로 그 동작을 보여 준다 (예: 쿠키 옵션 → FastAPI·`http.cookies`) |
| 3 | 📌 특징 | 이 개념을 다른 것과 구분 짓는 성질 |
| 4 | 🎯 써야 할 때 / 쓰면 안 될 때 | 각각 구체적 상황. 쓰면 안 될 때는 대신 쓸 것도 적는다 |
| 5 | ⚠️ 고려사항·주의사항 | 각 항목에 그대로 두면 벌어지는 실패 장면 하나 |

- 첫 설명은 다섯 부분을 모두 쓴다.
- 항목별 논의와 정정은 그 질문에 답하는 데 필요한 부분만 골라 쓴다. 단, 새 개념이 등장하면 1·2부터 쓴다.

## 1단계: 첫 설명

1. 입력에 든 질문 **전부**에 답한다. 질문이 여럿이면 질문마다 설명 틀을 적용하고, 개념 이름 하나면 그 개념을 설명한다.
2. 끝에 다음 단계를 안내한다: "읽고 궁금한 점을 목록으로 보내 주세요. 없으면 바로 확인 문제로 넘어갑니다."

## 2단계: 항목별 논의

1. 처음 목록을 받은 응답에서는 궁금한 점에 번호를 매겨 목록으로 먼저 보여 주고, 그 아래에서 1번을 시작한다.
2. 한 응답에는 **한 항목만** 다룬다. 항목을 시작하는 자리에 `[2/4] <항목>`처럼 진행 상황을 적는다.
3. 그 항목에 대한 후속 질문에는 계속 답한다. 사용자가 `다음`을 입력해야 다음 항목으로 넘어간다. 응답 끝에는 "더 궁금한 점은 이어서 물어보시고, 넘어가려면 `다음`을 입력해 주세요"처럼 넘어가는 방법을 적는다.
4. 논의 중 새 궁금증이 나오면 목록 끝에 추가했다고 알린다.
5. 마지막 항목에서 `다음`이 오면 3단계로 간다. 1단계 뒤에 궁금한 점이 없다고 하면 바로 3단계로 간다.

## 3단계: 이해도 확인 문제

1. 시작할 때 "총 N문제"를 알린다. 기본 5문제이고, 개념이 작으면 줄이고 논의한 항목이 많으면 늘린다.
2. 기술 면접처럼 **주관식 서술형**으로 낸다. 유형 예시: 코드를 보고 결과 맞히기, 상황을 주고 써야 할지 판단하기, 상황별 장단점·고려사항·주의사항 설명하기. 첫 설명과 논의한 항목에서 출제한다.
3. 한 응답에는 **한 문제만** 내고, 답을 받기 전에는 정답이나 힌트를 보이지 않는다.
4. 답을 받으면 먼저 `맞음 / 부분 정답 / 틀림` 중 하나로 판정하고, `맞은 점 / 틀리거나 빠진 점 / 모범 답안` 순으로 채점한다. 틀린 부분은 정정한다.
5. 채점 뒤 사용자의 질문에는 계속 답한다. 사용자가 `다음`을 입력하면 다음 문제를 낸다. 응답 끝에는 넘어가는 방법을 적는다.
6. 마지막 문제가 끝나면 판정별 문제 수와 다시 볼 부분을 짧게 정리하고 마친다.

## 흔한 실수

| 실수 | 바른 모습 |
|---|---|
| 궁금한 점 여러 개에 한 응답으로 모두 답한다 | 한 응답에 한 항목, `다음`을 기다린다 |
| 결론이나 정의부터 시작해 12살 눈높이 부분이 빠진다 | 첫 설명은 1번 비유부터 |
| 예제를 HTTP·JS 등 다른 형식으로만 보인다 | 파이썬 예제 코드를 반드시 넣는다 |
| "써야 할 때"만 쓰고 "쓰면 안 될 때"를 빠뜨린다 | 둘 다 쓰고, 안 될 때는 대안까지 |
| 문제와 정답을 같은 응답에 낸다 | 문제만 내고 답을 기다린다 |
