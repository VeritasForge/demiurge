# Custom Subagent 설계

커스텀 서브에이전트를 만들지 판단하거나, 만들 때 읽는다.

## 만들 것인가 — 내장이 먼저다

서브에이전트는 **별도 컨텍스트**에서 돌고 요약만 메인 대화에 반환한다. 조사·리뷰처럼
중간 산출물(파일 덤프, 시행착오)이 메인 컨텍스트를 오염시키는 작업을 격리하는 수단이다.

- 내장 서브에이전트(general-purpose / Explore / Plan)로 되는 일이면 만들지 않는다.
- **같은 전문 역할을 반복**하게 될 때만 커스텀으로 만든다 — 시스템 프롬프트·도구 제한·
  프리로드 지식이 매번 같아야 할 때.
- 스킬과의 구분: 스킬은 "지식·절차"를 현재 대화에 로드하고, 서브에이전트는 "역할"을
  격리 컨텍스트에서 실행한다. 지식만 필요하면 스킬이 싸다.

## 구조 — 마크다운 파일 1개

`.claude/agents/<name>.md` (프로젝트) 또는 `~/.claude/agents/<name>.md` (개인).

```markdown
---
name: pr-reviewer
description: PR 리뷰가 필요할 때 사용. diff를 읽고 버그·규약 위반을 보고한다.
tools: Read, Grep, Glob, Bash
skills:
  - payment-conventions
---
너는 이 저장소의 PR 리뷰어다. ...
```

## 필드별 판단 기준

- **description** — 메인 에이전트가 "언제 이 서브에이전트에 위임할지"를 이걸로 판단한다.
  스킬 description과 같은 원칙: 트리거 상황을 구체적으로.
- **tools** — 최소 권한. 조사 전용이면 쓰기 도구(Edit/Write)를 빼서, 잘못된 위임이
  파일을 건드리는 사고를 구조적으로 막는다.
- **skills** — 여기 나열한 스킬은 실행 시 본문이 **통째로 미리 로드**된다(온디맨드가
  아님). 항상 필요한 도메인 지식만 나열하고, 가끔 필요한 것은 빼라 — 서브에이전트도
  Skill 도구로 목록 밖 스킬을 호출할 수 있다.
- **model** — 역할 난이도에 맞게. 미명시 시 상속. 기계적 작업만 하는 에이전트에
  상위 모델을 고정하면 낭비, 판단 작업에 하위 모델을 고정하면 품질 저하가 조용히 생긴다.

## 시스템 프롬프트 본문

- 역할·판단 기준·출력 형식을 담는다. 메인 대화의 맥락은 전달되지 않으므로,
  "위에서 말한 것"류 참조는 성립하지 않는다 — 필요한 맥락은 위임 프롬프트로 넘긴다.
- 반환은 요약이다. "무엇을 어떤 형식으로 보고하라"를 명시해야 메인 에이전트가
  결과를 바로 쓸 수 있다.

## 우선순위 (같은 이름이 여러 레벨에 있을 때)

managed > CLI 플래그 > **project > user** > plugin. 스킬(managed > user > project)과
user/project 순서가 **반대**이므로 혼동 주의.
