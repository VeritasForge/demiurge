# 회차 맥락 파일 양식

회차 2 이후 모든 리뷰어 프롬프트의 맨 앞에 붙인다. 파일로 써 두고(`.autopilot-review/round-N/context.md`)
리뷰어에게 "먼저 이 파일을 읽으라"고 지시한다 — 프롬프트마다 같은 내용을 복사하면 회차가 갈수록 어긋난다.

이 파일이 하는 일은 셋이다: **어디를 먼저 볼지**, **무엇을 다시 올리지 말지**, **빈 결과가 답일 수 있음**.

```markdown
# N차 리뷰 공통 맥락

프로젝트: <한 문단. 무엇을 만드는지, 구조, 지켜야 하는 제약(저장 금지 같은 정책)>

작업 디렉토리: <절대경로> — 워킹트리가 곧 리뷰 대상이다. Read/Grep을 자유롭게 쓰라. git show는 쓰지 말 것.

## 리뷰 대상
- 최종 상태 전체 diff: <경로>/full.diff  (<기준> 대비)
- 변경 파일 목록: <경로>/files.txt
- **이번 회차에 새로 바뀐 부분(회귀 위험이 가장 높다)**: <경로>/round-(N-1)-changes.diff

## 이 리뷰의 목적
검토를 <N-1>차례 돌렸다. 발견은 <a> → <b> → <c>건으로 줄었고, 성격도 "<앞 회차 성격>"에서 "<지금 성격>"으로 옮겨 갔다.
회차마다 앞 회차 수정의 미비가 드러났다:
- 2차: <1차 수정이 만든 것 한 줄>
- 3차: <2차 수정이 만든 것 한 줄>
...
**이번 회차의 질문은 하나다: <N-1>차 수정이 새 결함을 만들었는가, 그리고 남은 것이 있는가.**

<후반 회차에만:>
**억지로 발견을 만들지 말 것.** findings가 빈 배열인 것은 실패가 아니라 수렴했다는 값진 답이다.
확신도 75 미만은 올리지 말고, 인용할 수 없으면 올리지 마라. 다만 진짜 결함을 찾았다면 등급과 무관하게 반드시 올려라.

## <N-1>차에서 고친 것 (이번에 회귀가 없는지 봐야 할 곳)
<파일별로: 무엇을 어떻게 바꿨는지, 왜. 리뷰어가 "그 수정의 형제 경로"를 떠올릴 수 있게 구체적으로>

## 이미 판단이 끝나 다시 올릴 필요가 없는 것
<보류 표가 있는 문서 경로>에 근거와 함께 기록됨:
<항목을 · 로 이어 한 문단>.
이것들을 그대로 다시 올리지 말 것. 다만 **새로운 실패 시나리오를 근거로 판단이 바뀌어야 한다면** 그 시나리오를 명시하고 올려도 된다.

## 현재 검증 상태(전부 통과)
<VERIFY 명령 목록과 시험 개수>
```

## 리뷰어 프롬프트에 함께 붙이는 고정 지시

```
- GitHub에 아무것도 게시하지 마세요. gh pr comment, gh api .../reviews, --comment 플래그 모두 금지입니다.
- 파일을 수정하지 마세요. 변형 실험은 반드시 격리 사본에서 하고, 끝나면 `git status --porcelain`이 비어 있는지 확인하세요 —
  같은 트리를 다른 리뷰어들이 동시에 보고 있습니다.
- 결과를 다음 모양의 JSON 객체 하나만 반환하세요: {"findings": [...], "coverage": [...]}
- coverage에는 "무엇을 확인했고 왜 문제가 없다고 판단했는지"도 적으세요 — 수렴 판단의 근거가 됩니다.
```

발견 스키마·등급·확신도 규약은 review-ensemble의 [merge.md](../../review-ensemble/merge.md)를 그대로 쓴다.

## 렌즈별로 덧붙이는 질문

회차 맥락은 공통이고, 렌즈마다 "이번 수정에서 특히 의심할 곳"을 두세 줄 더한다. 예:

- **시험 렌즈**: "앞 회차에 추가한 시험 목록. 각각 변형 실험으로 실제로 지키는지 확인하라. 특히 <검사 여러 개를 더한 곳>은 항목 하나씩만 어긋뜨려도 잡히는지."
- **주석 렌즈**: "앞 회차에 고치거나 새로 쓴 주석 목록. 그 근거가 실제 코드·라이브러리 동작과 맞는가. 특히 <다른 파일 값을 인용한 주석>."
- **적대적 관점**: "앞 회차에 넣은 방어들이 서로 어긋나거나 새 실패 경로를 만들지 않았는가. <시간값 사슬·취소 경로처럼 층이 여럿인 것>을 끝까지 따라가라."
- **보안 관점**: "앞 회차가 막은 유출 경로 <X>가 실제로 막혔는지 통제 실험으로 확인하고, 남은 경로를 찾아라."
