# PR 피드백 처리

리뷰 의견의 기술적 타당성은 기존 리뷰 수용 절차로 판단하고, 이 스킬은 코멘트별 작업과 GitHub 답글의 연결을 관리한다.

**필수 연계:** 현재 제공되는 `superpowers:receiving-code-review` 스킬을 읽고 피드백의 이해·코드 대조·반론·수정 판단에 적용한다. 스킬이 제공되지 않으면 그 사실을 알리고 원문과 실제 소스를 대조해 같은 판단을 수행한다. 이 파일에 다른 스킬의 지침을 복사하지 않는다.

1. PR의 인라인 리뷰 코멘트, 일반 대화 코멘트, 리뷰 본문을 읽고 작성자·원문 URL·코멘트 ID·대상 파일을 구분한다. 관련·중복 관계를 먼저 파악한다. 사용자가 코멘트별 논의를 요청했다면 중복이어도 코멘트 하나씩 설명하고 다음 항목으로 넘어가기 전에 응답을 기다린다.
2. 각 의견의 뜻을 실제 코드·테스트·문서와 대조한다. 해석이나 정책 선택이 남으면 사용자와 논의한다. 다른 코멘트의 불확실성이 현재 항목의 판단에 영향을 주면 함께 확인한다. `receiving-code-review`의 전체 중단 규칙보다 사용자의 명시적인 항목별 진행 요청을 우선한다. 코드로 독립성이 확인된 현재 항목만 진행하고 의존 항목은 먼저 논의한다. 수정이 필요하면 완료 조건을 정하고 변경·검증·차이 검토를 마친다.
3. 사용자가 커밋을 요청했다면 독립적인 변경마다 커밋한다. 동일한 변경으로 해결된 여러 코멘트에는 같은 커밋을 연결하고, 코멘트 수를 맞추기 위한 빈 커밋은 만들지 않는다. 게시할 답글에 해시를 쓰기로 했다면 해당 커밋의 원격 반영을 확인한 뒤 게시한다.
4. 답글 게시가 요청된 경우, 인라인 리뷰 코멘트에는 해당 스레드의 reply를 사용한다. 일반 대화 코멘트에는 원문 URL을 링크하고 원문을 인용문(`>`)으로 넣는 Quote reply 형식으로 답한다. 사용자가 지정한 답글 문구를 보존하고 게시 후 코멘트 본문·대상 URL을 확인한다. 게시 권한이 없거나 요청되지 않았다면 답글 초안만 제시한다.

완료 보고에는 처리한 코멘트별 커밋·답글 링크, 실제 실행한 검증과 남은 항목만 적는다.
