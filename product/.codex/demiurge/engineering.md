# 계획·구현·검증·하니스 관리 상세 기준

## 판단과 변경 범위

구현 전에 가정과 성공 조건을 밝힌다. 여러 해석이 가능하면 차이를 설명하고, 중요한
선택이 남으면 질문한다. 더 단순한 해결책이 있으면 제안하고 필요한 경우 근거를 들어 반대한다.
사소한 작업에는 판단에 필요한 만큼만 절차를 적용한다.

요구를 만족하는 최소 변경을 만든다. 요청하지 않은 기능, 한 번만 쓰는 추상화, 미래의
확장성, 실제로 발생하지 않는 상황의 오류 처리를 추가하지 않는다. 50줄로 가능한 작업을
200줄로 만들었다면 단순화할 수 있는지 검토한다.

관련 없는 코드·주석·포맷을 개선하지 않고 기존 스타일을 따른다. 이번 작업이 불필요하게
만든 코드만 정리한다. 기존의 무관한 죽은 코드는 사용자에게 알리고 임의로 삭제하지 않는다.
변경한 각 부분을 사용자 요청과 연결해 설명할 수 있어야 한다.

## 계획과 진행 추적

1. 전체 작업과 각 단계에 측정 가능한 완료조건·검증 명령을 적는다.
   입력 검증은 잘못된 입력의 테스트, 버그 수정은 재현 테스트, 리팩터링은 변경 전후 검증으로 구체화한다.
2. 현재 제공되는 스킬·에이전트 목록을 확인하고 각 단계에서 사용할 자산을 선택한다.
   이름이 비슷하다는 이유로 다른 런타임의 자산을 호출하거나 캐시 경로를 추측하지 않는다.
3. 참조하는 경로·심볼·설정을 실제로 확인한다. 기존 파일과 새로 만들 파일을 구분하고,
   존재하지 않는 파일이나 심볼을 이미 구현된 것으로 전제하지 않는다.
4. 사용 중인 작업 흐름의 진행 기록을 사용한다. 별도 추적 기능이 없으면 계획 파일의
   체크박스로 완료·진행·대기를 남긴다. 특정 도구가 모든 환경에서 비활성이라고 단정하지 않는다.
5. 각 단계 완료조건을 실제로 검증하고 출력과 한계를 확인한다. 실패나 새로운 사실이 드러나면
   원인을 분석하고 해당 작업을 수정·재수행한다.
6. 구현에는 작업 흐름의 리뷰를 적용한다. 그 기능이 없으면 사용 가능한 코드 리뷰 절차를
   최소 한 번 수행한다. React/Next.js 리뷰에는 설치된 Vercel 기준을 포함한다.
7. 마지막으로 전체 완료조건을 확인한다. 미충족 조건은 필요한 보완 작업과 함께 기록한다.

버전 하한·의존성·배포 범위 등의 실제 제약은 계획에 명시한다. 선택한 계획 스킬이 이미
기록한 항목을 반복하지 않는다. 되돌리기 어려운 변경, 보안 경계, 여러 프로젝트에 영향을
주는 설계에는 금지사항·고려사항과 추가 검토를 포함한다. 문서 품질·다관점 사실 검증을
모든 계획에 의무화하지 않는다.

## 추측하지 않는 진단·검증

- 설정 효과는 다른 조건을 고정하고 한 변수씩 확인한다. 여러 설정을 함께 바꿨다고 해서
  마지막 설정이 원인이라고 결론 내리지 않는다. 원인으로 지목한 설정만 바꾼 통제 실험으로
  인과관계를 확인하되, 실제 환경에 영향을 주는 실험은 허용된 범위에서 수행한다.
- 익숙한 사실도 최신성이 필요한 경우 공식 출처로 검증한다. 학습 데이터나 이전 세션의
  기억을 현재 설치 버전의 동작으로 확정하지 않는다.
- 호출 흐름·조건 분기·설계 의도뿐 아니라 주석과 다이어그램의 인터페이스·메서드 이름도
  실제 소스와 대조한다. 이름의 불일치나 중요한 호출 누락을 확인하고, 설명을 위해 단순화한
  부분은 실제 구현과 구분한다.
- '불가능하다'는 주장 전에 안전하고 작은 실험을 검토한다. 가짜 입력이나 격리된 대상에서
  검증할 수 있는 일을 환경 전체가 필요하다고 오해하지 않는다.
- '위험하다', '충돌한다'는 판단에는 언제 무엇이 실패하는지 구체적 상황을 적는다.
  성립하는 상황을 제시할 수 없으면 근거 없는 주장은 제거한다.
- 번역·요약·인용의 원문과 조건을 대조한다. 문서도 코드처럼 근거를 확인해야 한다.
  자세한 출처·인용 기준은 같은 디렉터리의 `communication.md`에서 확인한다.
- 실행하지 못한 검사와 실제 실패를 구분한다. 근거가 부족하면 판정 불가로 남긴다.

## 설치 자산과 역할 전달

플러그인 기능은 현재 세션에 노출된 스킬 목록·도구 명세로 확인한다. 디스크에 캐시가
있다는 사실만으로 활성화·호출 성공을 보장하지 않는다. 실제 사용 시 해당 SKILL.md와
필요한 참조를 읽으며, 다른 런타임의 예시 인자나 모델명을 그대로 복사하지 않는다.

Superpowers의 코드 리뷰 스킬은 포함된 리뷰어 프롬프트를 사용한다. 이것이 같은 이름의
등록 서브에이전트를 뜻하지는 않는다. 위임이 허용될 때 실제 사용 가능한 도구로 작업
범위·목표·검토 대상·검증 결과를 전달하고 결과의 근거를 확인한다. 수정·게시 허용 범위는
원래 사용자 요청을 넘기지 않는다. 여러 검증자가 같은 모델 계열이면 독립 모델 계열의
교차 검증이라고 부르지 않는다.

필수 자산을 사용할 수 없으면 대체 가능 여부와 범위 차이를 알린다. 사용할 수 없는
기능을 완료했다고 보고하거나, 설정 변경·새 설치를 원래 요청에 자동으로 포함하지 않는다.

## 저장소별 코드 탐색

작업 저장소의 `AGENTS.md`와 적용되는 하위 지침을 확인하고, 지정된 탐색 절차가 있으면 따른다.
프로젝트명·개인 경로·특정 인덱스 파일 형식을 전역 규칙으로 고정하지 않는다.

- 저장소가 제공하는 코드 인덱스·지식그래프가 있으면 관련 파일과 의존 관계를 좁히는 데 활용한다.
- 인덱스 형식과 메타데이터를 실제로 읽고, 생성 기준과 현재 소스·변경 내역을 대조한다.
  최신성을 확인할 정보가 없으면 그 한계를 밝히고 실제 소스를 기준으로 판단한다.
- 통제 흐름, 정확한 조건 분기, 보안 경계, 설계 의도, 문서 출처·귀속은 인덱스가
  최신이어도 원본 코드와 문서로 확인한다.
- 인덱스와 소스가 다르면 확인한 차이와 기준 시점을 알린다.
- 인덱스가 없으면 실제 코드와 저장소 문서를 직접 조사한다. 탐색을 위해 새 도구 설치나
  인덱스 생성을 요청 범위에 자동으로 추가하지 않는다.

## 하니스 수정과 배포

Demiurge가 관리하는 전역 지침은 배포 위치에 새로 복사하지 말고 저장소의
`product/.codex/` 원본을 수정한다. 배포 링크를 확인해 실제 저장소를 찾고 경로를 추측하지
않는다. 다른 저장소에서 작업 중이면 관련 파일과 아래 절차를 확인한 뒤 허용된 범위에서 수행한다.

- Codex 지침의 원본은 `product/.codex/`다. `just link`는 `product`와 `bin` 패키지 전체를
  함께 배포하므로 Codex 파일만 변경했어도 배포 영향 범위는 두 패키지 전체다.
- 스킬은 현재 Codex가 발견하는 사용자·프로젝트 `.agents/skills/` 또는 설치 플러그인의
  구조를 따른다. 새 전역 스킬을 Demiurge로 배포하는 구조는 별도 설계 대상이다.
  생성 명령은 실제 생성 경로와 형식을 확인한 뒤 사용한다. 현재 `just new-skill`·
  `just new-command`는 Codex 자산 생성에 사용하지 않는다.
- Codex 에이전트 정의와 스킬의 페르소나 참조 파일을 구분한다. 새 자산이 필요하면
  제공되는 제작 스킬·공식 문서로 형식과 지침 로딩 조건을 확인한다.
- 다른 에이전트에 하니스 수정을 맡기면 원본 위치·배포 범위·검증 조건도 전달한다.

소스 파일을 삭제하거나 옮길 때는 반드시 **소스가 존재하는 동안 링크 해제 → 소스 변경 →
재배포 → 검증** 순서로 한다. Stow는 현재 원본을 기준으로 링크를 해제하므로 역순이면
깨진 링크가 남는다. 공동 `just unlink`는 `product`와 `bin`의 관리 링크를 모두 해제한다.
다른 작업·프로젝트에 영향을 주는 배포는 요청 범위를 확인한다.

`just status`로 Codex 링크의 정확한 대상을 확인한다. Stow가 남긴 빈 디렉터리는 필요할 때
해당 자산의 좁은 범위에서 확인·정리한다. 빈 디렉터리 정리로 끊어진 링크 검사를 대신하지 않는다.
기존 일반 파일은 자동으로 덮어쓰거나 `--adopt`로 원본에 가져오지 않는다.

최초 전환의 기존 지침 대조·백업과 복구 절차는 저장소 README의 'Codex 최초 전환'을 따른다.
롤백도 링크 해제가 소스 원복보다 먼저다. Git 변경을 파괴적으로 되돌리는 명령을 임의로
실행하지 않는다. 링크 검사 성공과 새 Codex 세션의 지침 로딩 확인은 별도로 보고한다.
