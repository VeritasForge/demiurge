# 설명·질문·문서 작성 상세 기준

`AGENTS.md`에서 이 문서를 읽도록 정한 작업에 적용한다. 질문 도구·화면·렌더러의
지원 기능은 현재 Codex 실행 환경에서 확인하고, 제공되지 않는 기능을 가정하지 않는다.

## 설명과 가독성

- 맥락과 여러 관점을 함께 보고 결론에 이른 논리·판단 기준을 설명한다. 필요한 경우 단계와
  구체적 예시를 제공하고 대안·추가 확인 사항을 구분한다. 사용자가 다음 판단을 할 수 있게 쓴다.
- 헤더·리스트·표는 정보 계층을 명확히 할 때 사용한다. 이모지는 의미 전달에 도움이 되는 범위에서 사용한다.
- 복잡한 개념은 표·흐름도·시퀀스·ASCII 그림으로 설명한다. 세 주체 이상이 얽힌 경우 각 행위가
  어느 구간인지 먼저 보인다. 현재 화면에서 지원하는 형식을 사용하고 렌더링 여부를 추측하지 않는다.
  사례: A→B와 A→C를 모두 설명 없이 '호출'이라고 적으면 독자가 같은 구간으로 오인한다.
- 약어는 처음에 풀 이름과 함께 적고, 전문용어·등급은 사용 전에 짧게 정의한다. 도구나 서브에이전트
  출력의 약어를 옮길 때도 정의한다. 표에서 범주가 다시 나오면 필요한 범례를 제공한다.
  전문 보고서에 용어가 반복되면 용어집을 두되, 내부 라벨을 보존하기 위한 구실로 쓰지 않는다.
- 분류에 하위 의미가 섞여 있으면 설계 단계에서 구분한다. 사용자가 되묻고 나서 구분을 만들지 않는다.
- 사용자가 반복 콘텐츠의 전체 출력을 요청한 이후에는 같은 콘텐츠 수정에도 전체 내용을 제공한다.

## 사용자가 결정할 수 있는 질문

현재 사용할 수 있는 질문 도구를 확인하고 명세를 따른다. 적합한 도구가 없거나 그 사용이
제한된 상황이면 평문으로 질문한다. 앞선 대화나 터미널 출력을 읽었다고 가정하지 않는다.

1. 무엇을 결정할지 한 문장으로 밝힌다.
2. 질문이 나온 배경을 설명한다.
3. 선택지의 의미·결과·부작용을 구체적으로 설명하고 필요한 시나리오를 포함한다.

선택지 이름만으로 결정 내용을 알 수 있게 쓴다. 설명이 필요한 도구명·약어는 질문 안에서
풀어 쓴다. 질문 도구의 길이·개수 제한을 지키되, 결정에 필수적인 맥락은 생략하지 않는다.
사용자가 떠올릴 반문과 현실적인 우회 가능성을 먼저 검토한다.

- 맥락 없는 질문: 'T3에 DB 정리 단계와 해시 검증을 추가할까요?'
- 충분한 질문: '이미 실행한 서버의 기존 관리자 비밀번호도 무효화할까요? 초기 비밀번호를
  바꿔도 기존 데이터베이스의 비밀번호는 남을 수 있습니다. 이 단계를 포함하면 기존 계정도
  새 비밀번호로 갱신하고 이전 비밀번호의 로그인 실패까지 확인합니다.'

브라우저 자동재생 제약 때문에 대안을 물을 때도 '키 입력을 흉내 내면 되지 않나'라는
우회가 실제로 가능한지 확인하고, 불가능하다는 주장을 검증 없이 선택지의 전제로 쓰지 않는다.

중요한 답변과 선택 질문을 같은 질문 카드에 섞어 답변을 가리지 않는다. 답변을 먼저
제공하고 질문을 분리한다. UI가 턴 분리를 요구하면 다음 턴에 질문하고, 그렇지 않으면
독립적인 질문으로 제공한다. 현재 도구의 작동 방식을 확인한다.

사용자가 거부한 질문을 문구만 바꿔 반복하지 않는다. 거부는 아직 결정할 준비가 안 됐거나
대화로 먼저 이해하고 싶다는 신호일 수 있다. 무엇을 논의하고 싶은지 평문으로 좁히고,
구체적인 선택 의사가 드러나면 필요한 질문만 다시 한다. 같은 두 질문을 세 번 되풀이하는
방식은 문제의 맥락을 해결하지 못한다.

## 처음 읽는 사람을 위한 문서·플랜

- 무엇을 왜 하는지 → 작동 방식 → 현황 → 남은 일 → 주의사항 순서로 전개한다.
- 항목은 자체적으로 이해할 수 있게 쓴다. 필요한 이유, 바꿀 대상, 핵심 실행 방법·예시를 연결한다.
- 내부 라벨(P0-1, T3, Layer 3 등)은 가능한 한 실제 의미와 행동으로 바꾼다.
  결과 보고에 곁다리로 등장하는 도구 이름도 '코드 리뷰에서 주요 결함을 확인했다'처럼
  사람이 알아야 할 사실로 표현한다. 실행 지시와 도구·하니스 자체가 주제인 문서는 예외다.
- 대화 답변에서는 약어를 정의하거나 범례로 설명할 수 있지만, 사람용 결과 문서에서는
  불필요한 약어·내부 등급을 없애는 것을 우선한다. 약어를 각주로만 풀어 독자에게 넘기지 않는다.
- 추적되지 않는 설계·운영 문서로 설명을 떠넘기지 않는다. 독자에게 필요한 내용을 본문에
  포함하고, 링크를 제공한다면 실제 존재와 접근 가능성을 확인한다.
- 모르는 내용은 확정된 사실·가정·미확인으로 구분한다. 문서 형식 때문에 모든 칸을
  확정 판정으로 채우거나 '가장 큰 발견'을 억지로 만들지 않는다.

## 출처와 인용

번역·요약·발췌가 있으면 귀속 정보를 확인하고 원문을 연다. 원문에 접근할 수 없으면
'번역본 기준' 등으로 한계를 밝힌다. 인용에서 조건·수식어를 잘라 의미를 바꾸지 않는다.
차이를 주장할 때에는 해당 문장 전체의 의미와 앞뒤 문맥을 비교하고, 실제 출력하는 인용은
적용되는 인용 제한을 지킨다.

사례: Karpathy 지침을 번역만 보고 테스트 우선 요구가 없다고 판단하면 원문의 test-first
예시를 놓칠 수 있다. 또한 앞의 조건절을 빼고 인용한 뒤 '조건이 사라졌다'고 주장하면
실제 판본의 차이가 아니라 발췌 과정의 오류를 결론으로 만들게 된다.
